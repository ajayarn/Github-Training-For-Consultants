What is GitHub?

Think of it like a PowerPoint on SharePoint… but far more powerful.

On SharePoint, multiple people can open and edit the same PowerPoint. But if two people change the same part at the same time, the last save wins — and you lose track of who changed what.

GitHub automatically records every change with a name, a timestamp, and an author. You can always go back, see exactly what changed, and safely merge two people's work without conflict.
☁️ Cloud Storage

Files live online so the whole team always has access to the latest version

🕰️ Full History

Every change is recorded. Roll back to any point in time, instantly

🔀 Safe Collaboration

Work in parallel without stepping on each other's changes

✅ Review Process

Propose changes for teammates to review and approve before they go live

Part 2

Key Concepts

Plain-English definitions before we touch anything

The 6 Terms You Need

📦 Repository (Repo)
The project's home on GitHub. It stores all files, the full history of changes, and every branch. Think of it as a SharePoint folder — but with superpowers.
📋 Clone
Download a complete copy of the repository from GitHub onto your own laptop. You get all the files and the full history.
🌿 Branch
A separate, isolated workspace inside the repo. Changes you make on your branch don't affect anyone else's work. Think of it as your personal draft space.
💾 Commit
A saved snapshot of your changes, with a short message describing what you did. Like pressing "Save" — but every save is permanent and labelled.
⬆️ Push
Upload your local commits from your laptop to GitHub so teammates can see your work.
🔀 Merge
Combine your branch's changes into the main project. Usually done after a teammate reviews and approves your Pull Request.

Git vs GitHub — What's the Difference?

Git GitHub
Software that runs on your laptop and tracks changes to files A website and cloud service that hosts Git repositories online
Like PowerPoint's "Track Changes" feature — but built into your operating system Like SharePoint — but purpose-built for hosting Git repos
Works offline. No account needed. Needs an internet connection and an account.
Analogy: Git is the engine. GitHub is the car's dashboard and GPS. You technically only need the engine, but the dashboard makes everything much easier to use.

Getting Set Up

Two tools to install on Windows

Tool 1 — GitHub Desktop (Recommended)

🖥️ GitHub Desktop
A visual application — no command line needed. Click to clone, commit, push, and merge. Perfect for beginners.
https://desktop.github.com
Supports Windows 10 / 11 · Free · ~100 MB download
1
Go to desktop.github.com and click "Download for Windows"Run the installer (.exe). No admin rights required on most Bain machines.
2
Sign in with your GitHub accountIf you don't have one, create a free account at github.com first. A personal or work email both work.
3
You're ready!GitHub Desktop handles Git behind the scenes — you never need to open a terminal.

Tool 2 — GitHub CLI (Optional, Power Users)

⌨️ GitHub CLI (gh)
A command-line tool for users comfortable in a terminal. Manage repos, Pull Requests, and issues without opening a browser.
https://cli.github.com
Supports Windows 10 / 11 · Free · Install via winget or .msi installer
Install via Windows Package Manager
PS> winget install --id GitHub.cli
Then authenticate once
PS> gh auth login

Follow the prompts — it opens your browser to log in securely.

Part 5

The 5 Core Operations

Clone · Branch · Commit · Push · Merge

① Clone — Download the Project

What it does: Downloads a complete copy of the repository from GitHub onto your laptop — files, history, and all.

Analogy: Checking out a library book. You get your own copy to work on without altering the original on the shelf.
GitHub Desktop

File → Clone Repository → paste the repo URL → choose a local folder → Clone

Command Line
# Clone a repo
$ git clone <repo-url>

# Example:
$ git clone https://github.com/ajayarn/
  Github-Training-For-Consultants.git

⚡ You only clone once. After that, use pull to get the latest updates.

② Branch — Your Personal Workspace

What it does: Creates a separate workspace inside the repo where only your changes happen. The main branch stays untouched.

Analogy: Making a copy of a PowerPoint to edit, rather than touching the original. When you're happy, you merge your edits back in.
GitHub Desktop

Click the "Current Branch" dropdown at the top → "New Branch" → name it (e.g. anna/market-sizing) → Create

Command Line
# Create and switch to a new branch
$ git checkout -b anna/market-sizing

# List all branches
$ git branch

💡 Branch naming tip: use yourname/short-description, e.g. anna/market-model

③ Commit — Save a Snapshot

What it does: Records the current state of your files with a short message describing what you changed and why.

Analogy: Taking a photograph of your work and labelling it "Added Q3 revenue projections". You can always return to that exact photo.
GitHub Desktop

Changed files appear in the left panel → write a Summary (required) and optional Description → click "Commit to <branch>"

Command Line
# Stage all changed files
$ git add .

# Commit with a message
$ git commit -m "Add Q3 projections"

✍️ Good commit messages are short and descriptive: "Update market sizing assumptions", not "changes"

④ Push — Upload to GitHub

What it does: Sends your local commits from your laptop up to GitHub so your branch is visible to the rest of the team.

Analogy: Uploading a file to SharePoint. Your saved local snapshots are now online and shareable.
GitHub Desktop

After committing, a blue "Push origin" button appears in the top bar. Click it. Done.

Command Line
# Push your branch to GitHub
$ git push origin anna/market-sizing

# First time: set upstream automatically
$ git push -u origin HEAD

🔒 Pushing only affects your branch. Nobody else's work is touched until you merge.

⑤ Pull Request & Merge — Propose & Combine

Pull Request (PR): A formal proposal to merge your branch into main. Teammates can comment, request changes, and approve.
Merge: GitHub combines your changes into the main branch once the PR is approved.
1
Open a Pull RequestOn github.com → your repo → "Compare & pull request" button → add a title and description → click "Create pull request"
2
ReviewTeammates see your changes line-by-line, leave comments, and click "Approve"
3
MergeClick "Merge pull request" → "Confirm merge". Your changes are now in main. 🎉
4
Pull the latestEveryone runs git pull (or GitHub Desktop: "Fetch origin") to get the updated main branch on their laptops

Tips & Best Practices

🌿 Always work on a branch

Never commit directly to main. Always create a branch for your work, no matter how small.

💬 Write clear commit messages

Future-you (and teammates) will thank you. "Fix typo in slide 3" is better than "update".

⬇️ Pull before you start

Run "Fetch origin → Pull" each morning to get the latest changes before starting new work.

🔁 Commit often

Small, frequent commits are easier to review and easier to undo than one giant commit.

👀 Review before merging

Use Pull Requests even on small teams. A second pair of eyes catches errors and spreads knowledge.

🗑️ Delete merged branches

Once a branch is merged, delete it to keep the repo tidy. GitHub prompts you to do this automatically.
