Part 2

핵심 개념

실습 전에 꼭 알아야 할 용어 정리

꼭 알아야 할 6가지 용어

📦 Repository (Repo)
GitHub에 있는 프로젝트의 집. 모든 파일, 변경 이력, Branch가 저장되는 곳입니다. SharePoint 폴더라고 생각하되, 기능이 훨씬 강력합니다.
📋 Clone
GitHub의 Repository 전체를 내 노트북으로 다운로드하는 것. 파일과 모든 변경 이력이 함께 내려옵니다.
🌿 Branch
Repository 안의 독립된 작업 공간. 내 Branch에서 수정해도 다른 사람의 작업에는 전혀 영향이 없습니다. 개인 초안 공간이라고 생각하세요.
💾 Commit
변경한 내용을 짧은 메모와 함께 영구적으로 저장하는 것. 저장 버튼과 비슷하지만, 각 저장본이 영구 기록으로 남고 라벨이 붙습니다.
⬆️ Push
내 노트북의 Commit을 GitHub에 업로드하여 팀원들이 내 작업을 볼 수 있게 하는 것.
🔀 Merge
내 Branch의 변경사항을 메인 프로젝트에 합치는 것. 보통 팀원이 Pull Request를 검토하고 승인한 후 이루어집니다.

Git과 GitHub — 무엇이 다를까요?

Git GitHub
내 노트북에서 실행되는 소프트웨어로, 파일의 변경사항을 추적합니다 Git Repository를 온라인에서 호스팅하는 웹사이트이자 클라우드 서비스
PowerPoint의 "변경 내용 추적" 기능이 운영체제에 내장된 것과 비슷합니다 SharePoint와 비슷하지만, Git Repository 전용으로 만들어진 서비스입니다
오프라인에서 작동. 계정 불필요. 인터넷 연결과 계정이 필요합니다.
비유: Git은 엔진, GitHub은 자동차의 계기판과 내비게이션입니다. 엔진만 있어도 기술적으로 작동하지만, 계기판이 있으면 훨씬 사용하기 쉽습니다.

Part 5

5가지 핵심 작업

Clone · Branch · Commit · Push · Merge

① Clone — 프로젝트 다운로드

하는 일: GitHub에서 Repository 전체를 내 노트북으로 다운로드합니다. 파일과 모든 변경 이력이 함께 내려옵니다.

비유: 도서관에서 책을 대출하는 것. 내 사본을 받아 작업하며 서가의 원본은 그대로 남아 있습니다.
GitHub Desktop

File → Clone Repository → Repository URL 붙여넣기 → 로컬 폴더 선택 → Clone

명령어
# Repository Clone
$ git clone <repo-url>

# 예시:
$ git clone https://github.com/ajayarn/
  Github-Training-For-Consultants.git

⚡ Clone은 처음 한 번만 합니다. 이후에는 pull로 최신 내용을 받아옵니다.

② Branch — 나만의 작업 공간

하는 일: Repository 안에 나만의 독립된 작업 공간을 만듭니다. main Branch는 건드리지 않습니다.

비유: 원본 PowerPoint를 복사해 복사본에 수정을 하는 것. 만족스러우면 복사본의 변경사항을 원본에 반영하면 됩니다.
GitHub Desktop

상단의 "Current Branch" 드롭다운 클릭 → "New Branch" → 이름 입력 (예: anna/market-sizing) → Create

명령어
# 새 Branch 만들고 이동
$ git checkout -b anna/market-sizing

# 전체 Branch 목록 보기
$ git branch

💡 Branch 이름 팁: 이름/짧은설명 형식 사용 (예: anna/market-model)

③ Commit — 스냅샷 저장

하는 일: 변경한 내용을 짧은 메모와 함께 영구적으로 기록합니다.

비유: 작업한 내용을 사진으로 찍고 "Q3 매출 전망 추가"라고 라벨을 붙이는 것. 언제든 그 사진으로 돌아올 수 있습니다.
GitHub Desktop

변경된 파일이 왼쪽 패널에 표시됨 → Summary(필수)와 Description(선택) 작성 → "Commit to <branch>" 클릭

명령어
# 변경된 파일 스테이징
$ git add .

# 메시지와 함께 Commit
$ git commit -m "Q3 전망 추가"

✍️ 좋은 Commit 메시지는 짧고 명확합니다: "시장 규모 가정 업데이트" > "수정"

④ Push — GitHub에 업로드

하는 일: 내 노트북의 Commit을 GitHub로 전송하여 팀원들이 내 Branch를 볼 수 있게 합니다.

비유: SharePoint에 파일을 업로드하는 것. 로컬에 저장된 스냅샷이 이제 온라인에서 공유됩니다.
GitHub Desktop

Commit 후 상단에 파란색 "Push origin" 버튼이 나타납니다. 클릭하면 완료.

명령어
# 내 Branch를 GitHub에 Push
$ git push origin anna/market-sizing

# 처음에는 upstream 자동 설정
$ git push -u origin HEAD

🔒 Push는 내 Branch에만 영향을 줍니다. Merge 전까지 다른 사람의 작업은 건드리지 않습니다.

⑤ Pull Request & Merge — 제안하고 합치기

Pull Request (PR): 내 Branch를 main에 합치자는 공식 제안. 팀원들이 댓글을 달고, 수정을 요청하며, 승인할 수 있습니다.
Merge: PR이 승인되면 GitHub이 내 변경사항을 main Branch에 합칩니다.
1
Pull Request 열기github.com → 해당 Repository → "Compare & pull request" 버튼 → 제목과 설명 추가 → "Create pull request" 클릭
2
검토팀원들이 변경사항을 줄 단위로 확인하고 댓글을 남기며 "Approve" 클릭
3
Merge"Merge pull request" → "Confirm merge" 클릭. 이제 변경사항이 main에 반영됩니다. 🎉
4
최신 내용 받기팀원 전원이 git pull (또는 GitHub Desktop의 "Fetch origin")을 실행해 최신 main Branch를 내려받습니다
